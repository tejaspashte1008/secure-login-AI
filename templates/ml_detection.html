Academic Concept: Unsupervised Anomaly Detection via Isolation Forest

In authentication security, labeled attack datasets are scarce and attackers continuously change tactics. We employ Isolation Forest (Liu et al., 2008), an unsupervised tree ensemble algorithm. Anomalous login patterns (credential stuffing, velocity bursts, unusual hours) have distinct feature values and require significantly fewer random recursive partitions (shorter path lengths) to be isolated in tree nodes than normal user behavior.

Feature Engineering Breakdown
Feature Data Type Security Rationale
failed_attempts int (0 - 5+) Direct measure of credential mismatch count.
login_hour int (0 - 23) Captures diurnal access patterns (night-time vs daytime).
attempts_last_10m int (1 - 20) Measures velocity/frequency burst of attempts.
is_night_time binary (0/1) Indicator variable for high-risk off-hours (23:00 - 05:00).
Defense-in-Depth Principle:
The ML model provides risk augmentation, but the hard 3-attempt security lockout rule is strictly deterministic. Even if the ML model encounters an unseen feature or is temporarily offline, the rule engine guarantees lockout.

Model Evaluation & Academic Limitations
1. Cold-Start Problem
Unsupervised tree algorithms require representative distributions of baseline normal behavior. In new organizations with few users, anomalies must rely on rule-based fallbacks.
2. Legitimate Shift (False Positives)
A legitimate user logging in at 2 AM while studying for finals may trigger a higher anomaly risk score despite holding valid credentials.
3. Low-and-Slow Attacks
Sophisticated adversaries spreading attempts across hours or distributed IPs avoid velocity flags, which is why IP sliding windows and account lockouts are combined.
